# 周边去哪儿

根据用户给出的城市、起点坐标和自然语言需求，使用高德 MCP Server 完成一次“理解需求 → 查询地点 → 查询步行路线 → 筛选推荐”。只使用工具返回的事实，不填写或索要 API Key，不实现设备定位。

## 1. 理解需求

先提取并区分：

- **起点**：优先原样使用用户明确给出的经纬度，格式为 `经度,纬度`；所有路线必须使用这同一起点。城市用于消除地点歧义。
- **地点类型**：如咖啡馆、餐厅、公园；将“适合坐一会儿”等描述转成明确的搜索关键词，但不能把主观推测当成 POI 事实。
- **硬性条件**：步行时间上限、推荐数量、指定区域或地点类型。未指定数量时最多返回 3 个；指定更少时遵守用户数量，指定更多时仍最多返回 3 个。
- **排序偏好**：“近一点”按步行路线距离升序，“快一点/省时”按步行耗时升序。未明确时默认优先步行距离短。
- **其他偏好**：安静、排队少、营业中等只有在高德数据明确支持时才能用于筛选或描述，否则标注“未核实”，不得编造。

信息已足够时直接执行，不追问。缺少可用起点坐标时，说明需要起点坐标才能准确查询，不得猜测用户位置。

## 2. 搜索并整理候选

1. 调用高德周边搜索工具 `maps_around_search`：
   - `location`：用户起点坐标。
   - `keywords`：与需求匹配的简洁地点关键词。
   - `radius`：按需设置搜索半径；未设置时使用工具默认值。
2. 搜索结果用于召回候选。保留 POI 的 `id`、名称、地址、类型及工具实际返回的其他字段，按 `id` 去重；没有 `id` 时按名称和地址去重。
3. 排除类型明显不符、名称无效或重复的结果。不得仅凭品牌印象补充工具没有返回的地点。
4. 若周边搜索未返回目的地坐标，使用 POI `id` 调用 `maps_search_detail`，获取真实的 `location`、地址和类型。不要猜测坐标；无法取得坐标的候选不能进入路线规划。
5. 候选不足时，可合理扩大 `radius` 或使用同义关键词再次搜索，但不能因此放宽步行时间、地点类型等硬性条件。

`radius` 和搜索结果中的距离只用于召回或初步整理，均不代表实际步行距离或耗时，不能代替步行路线查询。

## 3. 获取真实步行路线

对整理后的合理候选池逐个调用 `maps_direction_walking`，不要只凭搜索顺序截取最终前 N 个：

- `origin`：始终是用户给出的同一起点坐标。
- `destination`：该候选 POI 的真实 `location`。

从返回的 `route.paths` 读取同一条实际路线的 `distance` 和 `duration`：距离单位为米，耗时单位为秒；展示时将秒换算为分钟。若有多条路径，选择一条符合用户偏好的路径，并始终使用该路径的距离和耗时，不得跨路径拼接数据。

记录每个候选的查询状态、路线距离和耗时。路线失败、没有路径或缺少有效距离/耗时的候选不得作为“符合条件”的推荐，也不得用直线距离、距离测量或经验速度估算替代。

## 4. 筛选与排序

1. 先按地点类型及其他可验证的硬性条件筛选。
2. 有步行时间上限 `T` 分钟时，仅保留原始路线 `duration <= T × 60` 的候选；边界值可以保留，超时候选不得列为符合条件的推荐。
3. 按用户偏好对合格候选排序：就近使用路线 `distance` 升序，省时使用 `duration` 升序；首要指标相同再比较另一项。
4. 排序后截取用户要求数量的结果，最多 3 个。推荐理由必须对应类型、地址、路线数据或高德明确返回的详情，例如“步行路线约 650 米，是符合 15 分钟条件的候选中距离最近的一家”。
5. 各地点都是从同一起点出发的独立备选，不要串成多站行程，不要把前一地点作为下一路线起点。

## 5. 回答格式

用简洁表格或编号列表给出最终推荐，每项必须包含：

| 地点名称 | 地址 | 预计步行距离 | 预计步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- |
| 高德返回的名称 | 高德返回的地址 | 同一路线的距离 | 同一路线的耗时 | 一句有数据依据的理由 |

按排序结果输出，使用原始路线数值完成筛选后再做适度展示取整。不要输出无关字段、冗长路线步骤或未经核实的宣传语。用户关心安静程度、排队、营业状态等而结果缺少依据时，在对应项简短标注“未核实”。

## 6. 无结果与异常

- **合格结果不足**：可以少推荐，说明“在本次已查询且成功获得步行路线的候选中，仅找到 X 个符合条件的地点”，不要把超时或路线失败的候选补足数量。
- **没有合格结果**：如实返回 0 个推荐，说明是搜索无结果还是路线筛选后无结果；可建议放宽步行时间、扩大搜索范围或调整地点类型，但不得擅自放宽后冒充原条件结果。
- **搜索失败**：说明高德地点查询暂时失败，不虚构地点；可在合适时重试一次。
- **部分详情或路线失败**：继续处理其他有效候选，并简短说明有候选因无法取得坐标或步行路线而未纳入；全部失败时明确说明无法生成可靠推荐。
- **信息缺失**：区分“高德未提供”与“未核实”，不要自行补全地址、距离、耗时、营业状态或主观评价。

最终只陈述本次高德调用能够支持的事实，不声称已经穷尽整个城市或所有附近地点。
